Build order

PHASE 0
Render pipeline + schema
Stand up Postgres from the data model. Write one Handlebars render function that reads htl-block-library/blocks/* directly — this is what both live preview and export will call. Register the partials/helpers the templates actually use (fixed org_chart's dangling person_card partial and major_projects_customisable's undefined custom_heading_or_default helper by inlining vanilla Handlebars). Wrap each section render in an error boundary.
PHASE 1
Auth, Dashboard, libraries
Session login. Dashboard card grid. CRUD for projects and the asset upload pipeline (signature validation, EXIF strip, hash-dedupe) — the Workspace's project-selection and upload panels are wired up here.
PHASE 2
Choose slides → Workspace
Two-step flow: pick which slides are in, then populate them. No versioning yet — everything writes to deck_sections only.
PHASE 3
Finalize → versions → links
Snapshot-on-finalize into deck_versions, export generation, deck_share_links token issuance, and the keep-vs-replace prompt.
PHASE 4
Public share page + hardening
Token-gated render route with the editor JS gated off by default (project_slide's editor now only attaches on <body data-deck-editor> — an exported/shared page never carries that flag). Sanitize free-text and raw-SVG fields at ingest, not just at render.
Deliberately cut from v1
PDF export (Playwright)
SVG asset uploads — raster only at launch
Per-link expiry / password wall
Multi-editor conflict resolution
Static-section text editing
Draft retention policy automation
